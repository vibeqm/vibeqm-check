1. **CORRECTNESS / check-weakening** — `src/checks/level2.ts` line 20  
   `git ls-files -- ...` lists the Git index, which includes files that are staged but not committed. A rules file that is only `git add`-ed will be counted as found, even though the comment and gate intent say clones and CI never see uncommitted files. This lets the check report `met` for a file that is not actually committed.  
   **Fix:** require the file to exist in `HEAD`, e.g. use `git ls-tree -r --name-only HEAD -- ${present}` (treating a missing `HEAD` as empty), or check `git cat-file -e HEAD:${f}` for each present file.

2. **CORRECTNESS** — `test/level2.test.ts` line 29  
   The helper named `commit` only runs `git add`, not `git commit`, so the tests do not exercise the committed-only behavior and mask the bug above.  
   **Fix:** after `git add`, run `git -C root commit -m test` (or rename the helper to `stage` and add a separate committed-file test).
